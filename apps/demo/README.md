# Fusion SLAM map explorer demo

The application is a **local read-only viewer** for existing FUSMAP2D
`.slammap` files and the active/previous `FUSGEN1` generation registry.
It does **not** stream robot poses or control SLAM.

From the repository root, use Python 3.10+:

```sh
python3 apps/demo/main.py --data-dir apps/demo/maps --example-if-empty
```

Open http://127.0.0.1:8765. With an empty map directory, the
`--example-if-empty` option displays a **schematic synthetic workshop**
(120 × 90 cells at 0.1 m) in a disposable temporary directory.
It is **not LiDAR data or a calibrated pose map**. It is never written to
`apps/demo/maps`. If you add your own `.slammap` export or `CURRENT`
generation registry, the real data takes precedence, including when it
is malformed. To use a different map folder, pass its path to `--data-dir`.

Like `civcode/hybrid-astar-cpp`, this repository also exposes a root
Dockerfile and Compose demo:

```sh
docker compose up --build demo
```

The Compose port is bound to **host loopback only**. Files inside
`apps/demo/maps` are mounted read-only at `/maps`. The container listens
on all of its own interfaces solely so Docker's loopback port forwarding
works; **do not publish the HTTP port publicly**, because the viewer
has no authentication. To run native SLAM tests manually:

```sh
docker compose run --build --rm test
```

For map format, CLI options and API details see
[the Web UI guide](../../docs/web-ui.md).

The browser explicitly labels the synthetic sample and never offers
map promotion or writes. The deterministic sample is generated by
[the example module](web/example.py) using the versioned C++ FUSMAP2D
layout; the native C++ inspector cross-checks it in CTest under
`demo_fixture_native`. The Python HTTP/CLI tests include empty-folder
startup, source precedence and damaged-registry behavior.
