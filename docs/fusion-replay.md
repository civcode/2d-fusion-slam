# Native Fusion Replay

The read-only C++20 Fusion Replay Web UI is at /fusion. The native HTTP
server displays artifacts generated by the C++ slam_offline_fusion executable;
it does **not** run the estimator, control a robot, or publish maps.

## Run it

~~~sh
cmake --build build --target slam_offline_fusion fusion_slam_demo
./build/slam_offline_fusion apartment apps/demo/fusion/apartment-001
./build/fusion_slam_demo --data-dir apps/demo/maps \
  --fusion-dir apps/demo/fusion --example-if-empty
# http://127.0.0.1:8765/fusion
~~~

The output directory must not already exist. The Docker Compose demo also
mounts apps/demo/fusion:/fusion:ro and apps/demo/maps:/maps:ro; generate runs
on the host, then refresh the browser. The original logged-LiDAR viewer
remains available at /replay.

## FUSFUSREPLAY1

Each completed run now has fusion_replay.json in addition to
fusion_report.json (FUSFUSION1), trajectories.json (FUSPOSES1), and
the named FUSMAP2D snapshots.

The new file includes the declared synthetic scene, source and matcher,
laser extrinsics, exact-decimal-string nanosecond timestamps and a bounded
array of frame events. Each frame contains its index, hits/beam counts,
sampled deskewed laser-frame endpoints, matcher attempted/accepted/status,
gate rejection reason, optional matcher geometry and frozen-map fingerprint,
cumulative accept/reject counts, map insertion flags, and optional
source-to-target GTSAM loop decisions for an independently simulated
relative-pose sensor.

Only **odd-indexed scans** were tested against the frozen even-only training
map; even indices are explicitly marked as training, not accepted matcher
queries. Sampling endpoints for the browser does not affect actual mapping
or matching. Graph loop decisions come from the GTSAM optimizer, not the UI.
Exact simulator truth remains separately labeled as scoring-only in FUSPOSES1;
the replay trace itself does not embed oracle poses.

## Native read-only API

| Endpoint | Response |
| --- | --- |
| GET /api/fusion/runs | Bounded direct-child run discovery |
| GET /api/fusion/runs/{id} | Validated FUSFUSION1 report |
| GET /api/fusion/runs/{id}/trajectories | FUSPOSES1 paths |
| GET /api/fusion/runs/{id}/replay | Complete FUSFUSREPLAY1 trace |
| GET /api/fusion/runs/{id}/frame/{index} | Individual trace frame |
| GET /api/fusion/runs/{id}/maps/{method} | Map metadata with report fingerprint verification |
| GET /api/fusion/runs/{id}/maps/{method}/image.png | Verified final occupancy PNG |

Run IDs are 1–80 ASCII letters/digits/underscores/hyphens. Methods are
wheel_only, lidar_only, gyro_wheel, fused_scan_matched and optional
graph_optimized. Paths never contain URL-controlled arbitrary filenames.
The server refuses symlinked run directories/artifacts, oversized files,
nonmonotonic or mismatched timestamps, mismatched scene/truth/clock, invalid
match/loop counts and nonmatching map fingerprints. There are no write
endpoints. FUSMAP2D's checksum is corruption detection, not authentication.

## Honest visualization

Use the timeline, play/pause, speed, previous/next, pan/zoom and layer
toggles to inspect actual run events and compare trajectories. The optional
synthetic ground-truth path is for *post-run scoring only*.

**The occupancy PNG and optimized graph solution are final post-run
outputs**, not intermediate snapshots that existed at the replayed time.
The accumulating green dots represent transformed sampled **observed
LiDAR return endpoints**, not evolving log-odds occupancy. Method RMSE,
coverage and IoU are from the completed independent synthetic evaluator.
There are no real hardware timing/calibration or robot localization claims.

## Local verification

~~~sh
cmake --build build --target \
  slam_offline_fusion fusion_slam_demo slam_map_accuracy_cli --parallel 2
ctest --test-dir build \
  -R 'offline_fusion|fusion_replay_http|native_web_api' \
  --output-on-failure
~~~

The fusion_replay_http CTest executes the actual native offline fusion CLI
and native HTTP server, checks metadata and frame parity, validates PNG/map
fingerprints, and tests corrupt/symlinked inputs and denied HTTP writes.

**Status:** source and tests were committed directly to main, preserving
the user's intervening build/test fixes. A full native CMake/CTest/Docker
execution is not verified in this ChatGPT container because GitHub cannot
be cloned to its local filesystem. No GitHub Actions were run.
